# DS·Train — Virtual Patient Diagnostic System

A medical education platform that simulates clinical diagnostic sessions using an AI-powered virtual patient. Students practice differential diagnosis by questioning a virtual patient and ordering tests, receiving real-time feedback on the quality of their clinical reasoning.

---

## Overview

DS·Train combines a **biomedical knowledge graph**, **BioBERT embeddings**, and an **information-theoretic patient model** to simulate realistic diagnostic encounters. The system evaluates student performance across three dimensions: information gain, protocol adherence, and communication quality.

```
Student asks a question
        ↓
Virtual Patient answers (rule-based or LLM-powered)
        ↓
PatientModel updates diagnosis probability distribution
        ↓
Shannon entropy measures diagnostic uncertainty reduction
        ↓
EvaluationEngine scores the step
```

## Architecture

### Core Modules

| File | Role |
|---|---|
| `Preprocessing.py` | Builds the knowledge graph from raw patient data |
| `BioBert.py` | Vectorises graph nodes using BioBERT embeddings |
| `PatientModel.py` | Bayesian-style belief model over diagnoses |
| `AdaptiveQuestionSelector.py` | Selects the highest information-gain next question |
| `VirtualPatient.py` | Rule-based virtual patient (cosine-similarity answers) |
| `SmartVirtualPatient.py` | LLM-backed virtual patient (Gemma 3 via Ollama) |
| `VirtualPatientEngine.py` | HTTP connector to a local Ollama instance |
| `Evaluation.py` | Scores each step and generates a session report |
| `SessionMDP.py` | MDP framework — computes regret vs. optimal policy |
| `BaseScoringLogic.py` | Shannon entropy, softmax temperature schedule |
| `UtilsBert.py` | Shared BioBERT encoder & translation utilities |
| `Markov.py` | CLI entry point for automated test sessions |
| `app.py` | Flask + Socket.IO web application |

### Frontend

| File | Role |
|---|---|
| `index.html` | Single-page application shell |
| `style.css` | UI styles |
| `script.js` | Socket.IO client logic |

## Setup

Run the three preparation steps in order. Each step saves its outputs to `DataSaves/`.

### Step 1 — Build the Knowledge Graph

```bash
python Preprocessing.py
```

Parses conditions and evidences, builds a weighted symptom–diagnosis graph, and saves:
`adjacency_matrix.npy`, `graph_metadata.json`, `symptom_names.json`, `symptom_questions.json`, `diagnosis_tests.json`, `knowledge_graph.pkl`

### Step 2 — Vectorise Graph Nodes with BioBERT

```bash
python BioBert.py
```

Encodes all diagnosis and symptom nodes into 768-dimensional BioBERT vectors and saves:
`diagnosis_vectors.npy`, `symptom_name_vectors.npy`, `procedure_vectors.npy`, `node_vectors.pkl`

### Step 3 — Launch the Web Interface

```bash
python app.py
```

Open [http://localhost:5000](http://localhost:5000) in your browser.

## Usage

### Web Interface

1. Select a patient mode:
   - **Smart Patient** — answers are generated by Gemma 3 via Ollama (requires Ollama running locally)
   - **Simple Patient** — answers are generated by cosine-similarity lookup (no LLM required)
2. Select interface language (Ukrainian / English)
3. Read the patient's initial complaint
4. Type questions in natural language and submit them
5. Order diagnostic tests via the 🔬 button
6. Submit your final diagnosis when ready
7. Review your competency report

### CLI (Automated Test Session)

```bash
python Markov.py
```

Runs a fully automated diagnostic session where the `AdaptiveQuestionSelector` asks questions on your behalf, printing step-by-step information gain and a final evaluation report.

## How Scoring Works

### Information Gain (ΔH)

At each step the system measures the reduction in Shannon entropy over the diagnosis distribution:

```
ΔH = H(S_t) − H(S_{t+1})
```

A larger ΔH means the question was more diagnostically useful.

### Step Score

```
score = w1 · ΔH + w2 · R_protocol − penalty + comm_bonus
```

- **R_protocol** — cosine similarity between the student's action and gold-standard clinical procedures
- **penalty** — applied when the action resembles a red-flag (contraindicated) intervention
- **comm_bonus** — based on politeness and empathy pattern matching

### MDP Regret

`SessionMDP` computes the optimal action at every step via exhaustive one-step lookahead and reports the student's regret relative to the optimal policy.

## Configuration

Key parameters can be adjusted directly in the relevant modules:

| Parameter | Location | Default | Effect |
|---|---|---|---|
| `beta` | `PatientModel` | `0.3` | Symptom signal strength |
| `decay` | `PatientModel` | `0.96` | Score decay per step |
| `top_k` | `PatientModel` | `3` | Sparse symptom activations |
| `tau_start / tau_end` | `BaseScoringLogic` | `1.2 / 0.35` | Temperature annealing schedule |
| `N_STEPS` | `Markov.py` | `12` | Max steps per session |
| `similarity_threshold` | `VirtualPatient` | `0.80` | Minimum cosine sim to reveal a symptom |

N_STEPS - only applies to question selector.

---

## Notes

- The first run of each session will download BioBERT (~440 MB) from Hugging Face if not already cached.
- Question embeddings are cached to `DataSaves/question_embeddings_cache.npz` to speed up subsequent sessions.
- Smart Patient mode requires Ollama to be running: `ollama serve` and `ollama pull gemma3:12b`.
- The evaluation protocols in `Evaluation.py` include examples for a small set of diagnoses. Extend `EvaluationEngine.DEFAULT_PROTOCOLS` or load a custom JSON file via `EvaluationEngine.from_json()` to cover more conditions.
